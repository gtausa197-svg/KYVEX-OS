# KYVEX OS 0.5 Alpha — Rift Engine 0.1

Rift Studio — власна нативна програма KYVEX на C++20 / Qt 6 / QML.
Рушій та сервіс написано на Rust 2024. Бібліотека використовує SQLite,
профілі керування — версійований JSON, зв’язок — приватний Unix socket.
Попередні можливості KYVEX 0.4 збережено.

## Що реалізовано з плану

Робочий початковий прототип: сервіс, IPC, бібліотека APK, перевірка ZIP,
бінарного Manifest, DEX та ABI, редактор прив’язок із перетягуванням,
Undo/Redo, автоматичне збереження, імпорт/експорт профілів, тестове вікно
дотиків, Tap/Hold, WASD-джойстик, жести та прицілювання правою кнопкою миші.
Кожен дотик має свій ID; втрата фокуса / зв’язку відпускає натискання.

Власний експериментальний DEX-інтерпретатор виконує обмежені цілочисельні
інструкції з перевірками меж і лімітом кроків. Тест обчислює 6 × 7 = 42.
Повні ART / JNI / Android Framework / Bionic / власний ARM JIT ще не реалізовано.
Справжні APK працюють через сумісний Android-бекенд Waydroid, ARM — через
окремо встановлюваний libndk. Це початковий етап плану, а не завершення всіх
етапів власної Android-платформи.

## Перший запуск, включно з Live

1. Відкрийте KYVEX Control Center → App Bridge → Open Rift Studio.
2. Runtime → Set up Android. Завантажується офіційний Vanilla Android.
3. Start Android. Для ARM на AMD / Android 13 натисніть Enable ARM,
   потім Stop Android → Start Android після перезапуску контейнера.
4. Authorize local controls підтверджує ваш локальний відкритий ADB-ключ
   через штатне вікно адміністратора. Приватний ключ не копіюється;
   перевірка автентичності ADB залишається увімкненою.
5. Import APK або перетягніть файл у бібліотеку. Імпорт лише перевіряє і
   зберігає APK; Launch запускає його. Подвійне натискання APK у Dolphin
   відкриває Rift, імпортує та запитує запуск.

Live потребує інтернету для першого налаштування Android / ARM. Мінімум
16 ГіБ загальної RAM, 8 ГіБ вільної RAM та 7 ГіБ вільного тимчасового сховища
перевіряються перед завантаженням. Для Live-ігор рекомендовано 24 ГіБ RAM.
Android, APK, профілі та зміни Live зникнуть після перезавантаження.
Для Android створюється окрема тимчасова файлова система в RAM: це дозволяє
підключити ARM-бібліотеки через OverlayFS і не залежати від накладання Archiso.
Жоден фізичний диск автоматично не форматується і не обирається для Android.
Щоб зберегти профіль, експортуйте JSON на власний носій перед завершенням Live.

## Ігрове керування

Game Controls → виберіть пакет. Перетягніть кнопки, призначте клавіші,
відредагуйте координати та кінцеву точку жесту. Профіль зберігається автоматично.
Test scene показує справжні згенеровані дотики без Android.

Для Android: Game display перезапускає користувацький сеанс з одним Android
екраном. Максимізуйте його; виберіть відповідну орієнтацію та роздільність,
потім Android overlay. Воно прозоре й захоплює клавіатуру лише у фокусі.
Esc закриває накладання, F1 перемикає перегляд прив’язок. Desktop display
повертає окремі вікна застосунків. Зміна роздільності потребує повторного
підключення накладання; Unity-ігри також можуть потребувати перезапуску
застосунку після зміни роздільності. Повного захоплення відносної миші, геймпадів та
редактора довільних макросів у цьому прототипі немає.

Для com.kiloo.subwaysurf є початковий профіль: стрілки — жести, Space — дотик.
Game Controls → Application architecture дозволяє зберегти Auto, ARM32
(armeabi-v7a), ARM64 (arm64-v8a), x86 або x86_64 окремо для кожного APK.
Варіант повинен бути присутній у файлі. Для наданого Subway 3.71.0 перевірявся
ARM32; виберіть armeabi-v7a перед запуском. Авторизований локальний канал
очікує завершення встановлення APK, включно з підготовкою DEX, перед запуском.
Для активації функції гри, яка потребує подвійного дотику, двічі натисніть Space.
Фактичний статус Subway Surfers 3.71.0 та результати Live постачаються у звіті
перевірки; наявність стартового екрана сама по собі не означає повну сумісність.
Ігровий APK користувача не включено до ISO чи архіву вихідного коду.

## Межі прототипу

Split APK / XAPK поки відхиляються з поясненням. Якщо назва / іконка
вимагає повного розбору Android Resources, бібліотека показує назву пакета
та власну монограму. Remove вилучає запис і збережений APK із бібліотеки;
дані встановленої Android-програми зберігаються. Видалення Android-застосунку
доступне в його штатних налаштуваннях.

Без GPU, який підтримує Android-бекенд, використовується SwiftShader;
це не означає ігрового прискорення. Фізичні NVIDIA / AMD / Intel потребують
окремих тестів. Програми з DRM, Play Integrity та вимогами Google-сервісів
можуть не працювати у Vanilla Android. Гарантії відсутності всіх помилок немає.

Документація вихідного коду: rift/README.md. Попередні функції Windows,
живлення і мов описано у RELEASE-0.4.uk.md.
